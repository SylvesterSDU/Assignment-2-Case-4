Does it match? Yes. The documentation says Gemini was built by the Gemini team at Google DeepMind, together with teams across Google.
Note: a model does not "know" who made it from its training text. The developer puts this answer in on purpose, through the assistant training data and/or the system prompt. Without that, a model trained on internet text could just as well say it was made by OpenAI, because that answer is so common online.

--- Comparison: which were correct, and why? ---
All four answers were correct (€930.46), including the non-thinking model asked for only the final answer.
The main reason is that Gemini used a tool: in three of the four runs a "Vis kode" (show code) button appeared,
meaning the model wrote and executed code instead of doing the arithmetic in text. So this test mainly shows the
effect of tools, not the difference between thinking and non-thinking models. Without code, a non-thinking model
asked for only the final answer would have to produce the whole result in one go, which is where errors are most
likely; showing the calculation, or thinking first, gives the model more tokens to work through the steps.
Both "show the calculation" runs reached the result in slightly different but equivalent ways
(963 net units x 57.112 vs. 1,035 sold minus 72 refunded), which is useful for checking the logic.

### WHAT I NOTICED

Hallucinations and context: from memory alone, the model either admitted it did not know (when asked to) or gave approximate answers with an extra unrequested detail. With the article in the context, or with web search, every answer was correct. For business questions, give the model the actual document or let it retrieve current information instead of relying on its memory.

Who created you: the answer ("Google") matched the documentation, but the model knows this only because the developer trained or prompted it to say so.

Thinking vs. tools: all four profit answers were correct, but Gemini ran code in three of them ("Vis kode"). The tool, not the thinking, did the arithmetic. This is why invoice totals should be checked with executed code rather than a fluent explanation.

Tokens: the decimal and counting questions were right, which these tasks were famous for getting wrong in older models (probably trained in by now). But every third character of "Ubiquitous" was wrong twice ("bio" and "btu"). The model sees tokens, not single letters, so letter-level tasks are hard. Even when I asked it to use code, it gave a wrong answer with no sign that code had actually been run: asking for a tool does not guarantee the tool is used, so check that it was.
